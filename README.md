# AI 阅读器（ai-reader）

> 一个本机内容整理工具：抓取和清洗用户有权访问的网页或 PDF，在本机生成易读的内容页。

## 项目背景

在使用大语言模型时，经常遇到这样的障碍：想整理一篇微信公众号文章、一条小红书笔记或一个 PDF，但原网站需要登录，或内容藏在图片里，难以直接阅读和归档。

AI 阅读器解决的就是这个"技术上访问不了"的问题：

```
原网站或 PDF → 本工具抓取、清洗 → 本机阅读页
```

对使用者而言，全程只有三步：**粘贴链接或上传 PDF → 获取本机阅读链接 → 在本机浏览器打开**。

本项目坚持一条边界：**只解决技术访问问题，不绕过付费墙、不破解验证码、不获取用户无权访问的内容。**

## 功能特性

| 来源 | 支持情况 | 说明 |
|---|---|---|
| PDF | ✅ | 本地文件文字提取 |
| 微信公众号 | ✅ | 文章正文提取，转为干净 Markdown |
| 小红书 | ✅ | 真人登录态复用，提取笔记正文、图片文字和评论（见下） |
| B 站字幕 | ⏸️ 暂停 | 当前不提供真实抓取 |

**小红书笔记按三个分区输出，对 AI 阅读友好：**

```markdown
## 图片文字      ← 本机 OCR 最多处理 9 张笔记图片
## 正文          ← 笔记正文
## 高赞评论       ← 默认顺序前最多 50 条一级评论，过滤后的昵称 + 内容
```

## 工作原理

工具由四个模块组成，内容依次流过：

1. **入口** — 粘贴链接或上传 PDF，自动识别类型并分发。
2. **抓取器** — 按来源分支处理：PDF 解析、公众号和小红书均通过有界面的 Edge 获取用户可访问的内容。
3. **清洗器** — 提取正文、剥离广告导航，转为 Markdown。
4. **发布器** — 存储后生成随机链接 `/read/{slug}`，由服务端直接返回纯内容（不依赖前端 JS）。服务只监听本机回环地址，阅读链接只能在运行服务的这台机器访问，不能供云端 AI 或其他设备直接访问。

## 技术栈

| 层 | 选型 |
|---|---|
| 语言 | Python 3.11+ |
| Web 服务 | FastAPI + uvicorn |
| 浏览器自动化 | Playwright（驱动本机 Edge，持久化登录态） |
| PDF 解析 | PyMuPDF |
| 正文提取 / 转 Markdown | trafilatura / markdownify |
| 图片文字识别 | RapidOCR（本机 CPU 推理，不调用云端 OCR 服务） |
| 存储 | SQLite |

## 快速开始

> 环境：Windows + Python 3.11+。首次运行需手动在弹出的浏览器中登录相关站点。

```powershell
# 1. 创建虚拟环境并安装依赖
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt

# 2. 启动服务
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

本机需安装 Microsoft Edge；Playwright 通过 `channel="msedge"` 使用系统 Edge，不需要运行 `playwright install chromium` 下载独立浏览器。启动后打开 `http://127.0.0.1:8000/`。

小红书首次使用时，在入口页点击“打开小红书登录”，由本人在弹出的 Edge 窗口登录，再回到入口页点击“我已完成登录”，然后提交笔记链接或分享文本。公众号抓取也使用有界面的 Edge。PDF 可直接上传。

停止服务请在启动服务的 PowerShell 窗口按 `Ctrl+C`。

运行项目测试：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

## 关键设计与取舍

这些是项目中我做过的主要产品与工程决策：

- **合规边界优先**：真人登录后访问自己有权看的内容属于正常访问，予以支持；但验证码、人机验证、风控拦截一律立即停止、不绕过。这条边界贯穿每个抓取器。

- **"可控浏览器 + 真人登录"方案（做法 B）**：面对小红书的登录与环境检测，采用由使用者本人在可控浏览器中登录一次、程序持久化复用登录态的方式。既解决了访问问题，又不触碰破解类手段，凭证只存在本机、不进入代码或日志。

- **发布页极简**：阅读页由服务端直接返回纯内容，便于在本机浏览器或命令行读取；服务仅监听 `127.0.0.1`，不作为外部 AI 的远程读取链接。

- **突破小红书图片懒加载**：小红书图片以非标准方式渲染、且滚动才挂载。通过检查真实页面 DOM 定位到实际图片节点与加载时序，再用本地 OCR 识别，拿到了"藏在图片里"的内容。

- **优雅降级而非硬失败**：小红书笔记常无独立标题，则用正文首行兜底；单张图片识别失败不影响其余内容；OCR 不可用时整条抓取仍返回正文与评论。

- **纯本地、注重隐私**：第一期只在本机运行，登录态、数据库和本地配置保存在本地，不上传第三方。OCR 在本机执行，不调用云端 OCR 服务。

## 本地数据与清理

- `data/reader.db` 保存已发布内容；`data/browser_profile/` 保存 Edge 登录态；`data/tmp/` 用于临时文件。这些均为本地敏感数据，不要分享或提交。
- 当前 PDF、公众号和小红书流程不需要 `.env`。`.env.example` 中的 B 站配置对应暂停功能，不代表 B 站抓取当前可用。
- 删除单条已发布内容：在项目根目录运行 `\.venv\Scripts\python.exe -c "from app.publisher import delete_document; print(delete_document('你的slug'))"`。删除后该阅读链接返回 404。
- 清空本地数据库或登录态前，先停止服务。删除 `data/reader.db` 会移除全部已发布内容；删除 `data/browser_profile/` 会清除保存的浏览器登录态。
- `.env` 和整个 `data/` 均由 `.gitignore` 排除，不应进入 Git 提交。

## 使用边界与合规

本工具仅供个人学习与自用，仅处理使用者有权访问的内容。不得用于批量采集、商业分发，或绕过付费墙、验证码、人机验证与平台风控。涉及登录的站点请由本人正常登录并控制访问频率；遇到平台验证或风控提示立即停止。服务只绑定 `127.0.0.1`，不要配置公网隧道或反向代理。生成的 `/read/{slug}` 链接仅供运行服务的本机访问，不可作为云端 AI 可访问链接验收。
